02 / Introduction

The business question is about reusability.

Frame the outcome correctly before comparing models.

Question

Which launch conditions are associated with a successful first-stage recovery?

Falcon 9's reusable first stage can reduce launch cost. For a launch provider evaluating a competitive bid, landing reliability matters because it changes how often hardware can be recovered and flown again.

09 / Predictive methodology

Classification tests signal - the validation design matters.

Reported pipeline, with the key risk made explicit.

Inputs
90 x 83

90 launches; 83 numeric/one-hot encoded features. Target: first-stage landing class.

Split
72 / 18

80/20 train-test split with random_state = 2.

Models
LR / SVM

Logistic regression, support vector classifier, and decision-tree tuning.

Notebook workflow

1

Scale featuresStandardScaler transforms the encoded feature matrix.

2

Search parametersGridSearchCV uses 10-fold CV; examples include C for logistic regression and C/gamma/kernel for SVC.

3

Score and inspectEvaluate the selected estimator and plot a confusion matrix.

Validation risk

Leakage in saved workflow: preprocessing and hyperparameter search are fit using all 90 observations before scoring the 18-row test split. The holdout is therefore not independent.
  • Put scaling inside a Pipeline.
  • Run GridSearchCV on training data only.
  • Use stratified folds and keep the test set untouched until final evaluation.
  • Report precision/recall and a confusion matrix, not accuracy alone.

11 / Innovative insight

Three snapshots, three questions - don't collapse them.

A data lineage check changes how every headline is read.

SQL snapshot
101

Archived rows used for mission/landing SQL queries.

Model snapshot
90

Encoded feature rows for recovery classification and EDA.

Map/Dash snapshot
56

Rows in the saved geospatial and dashboard extract.

Why it matters

The snapshots differ in row counts and fields. A site rate from the 56-row dashboard should not be compared directly with a site rate from the 90-row model sample as if both came from one table.

Second signal: recovery is a learning curve

Year-level success rises from 0% in 2010-2013 to mostly above 80% in 2017-2020. Meanwhile success is higher for heavier payload rows in this sample - likely reflecting launch era, booster maturity, and mission mix rather than payload mass alone.

Novel takeaway: aligning snapshot provenance and separating mission outcome from recovery are prerequisites for a fair business comparison - and probably more valuable than adding model complexity.
12 / Conclusion

Build the evidence chain before acting on the score.

What an analyst should take forward.

Conclusions

  • First-stage recovery becomes more common in later records, consistent with operational learning and hardware evolution.
  • Launch site, orbit, payload, booster, and time all shape the observed outcome; no single variable explains recovery.
  • SQL, visual EDA, Folium, and Dash make different parts of the story inspectable.
  • The 94.4% saved test score is not a dependable forecast because the pipeline leaks test information.

Recommended next steps

1

Reconcile inputsPublish one versioned analysis table and document row-level inclusion rules.

2

Validate honestlyUse a leakage-safe pipeline and a time-aware holdout for future launches.

3

Communicate uncertaintyShow denominators, class balance, calibration, and subgroup performance.

4

Keep the tools liveUse the site/payload dashboard for exploration, not automated launch decisions.
